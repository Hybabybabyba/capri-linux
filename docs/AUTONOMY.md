# Автономность Капри

Капри перестаёт быть «чатом с аватаркой» и становится фоновым процессом, который сам замечает
события в системе и говорит только тогда, когда это экономит внимание. Главный принцип: **молчать
по умолчанию**. Каждое проактивное сообщение проходит через «бюджет внимания» (дедупликация,
кулдауны, тишина в полноэкранном окне, молчание, если ты и так смотришь на источник события).

## Где уходит внимание на Arch + Hyprland

| Боль | Почему её стоит автоматизировать | Чем ловить без LLM |
|---|---|---|
| Ждать билд / `paru -Syu` / `docker build`, проверяя терминал каждые 30 с | постоянные переключения контекста | zsh `preexec`/`precmd` → длительность, код выхода |
| Разбирать, почему упало, копируя лог в браузер | рутинная работа, LLM тут реально полезна | хвост вывода из kitty (`get-text --extent last_cmd_output`) |
| Обновление сломало систему: пропущенные новости Arch, `.pacnew`, упавшие юниты | узнаёшь постфактум, когда уже поздно | `checkupdates`, RSS archlinux.org, `systemctl --failed`, `coredumpctl` |
| Стектрейс / ошибка / хэш в буфере обмена | копируешь, чтобы потом куда-то вставить и спросить | `wl-paste --watch`, локальная классификация регулярками |
| Каждый раз раскладывать окна под проект | одинаковые 10 действий каждое утро | `hyprctl dispatch`, события socket2 |

## Пять функций

### 1. Build Watchdog — **реализован** (`services/watchdog.js`, `hooks/capri.zsh`)
- **Что даёт:** запускаешь `cargo build`/`makepkg`/`paru -Syu` и уходишь в браузер. Капри сама скажет
  «готово за 4 мин 12 с» или «упало с кодом 101» и одной фразой назовёт причину.
- **Проактивность:** zsh-хук после каждой команды дольше `CAPRI_MIN_SECONDS` (10 с) шлёт событие в
  сокет. Watchdog проверяет, на какое окно ты смотришь: если активное окно Hyprland — предок шелла
  по дереву процессов, она молчит (до 2 мин). Интерактивное (`nvim`, `ssh`, `htop`, `less`…) и
  Ctrl+C/Ctrl+Z игнорируются.
- **При падении:** хвост вывода берётся из kitty, секреты (`gsk_…`, `ghp_…`, `password=…`) вычищаются,
  Groq с отдельным коротким промптом выдаёт причину. Событие попадает в историю диалога: в HUD можно
  сразу написать «почини», и она знает, о чём речь.
- **Канал доставки:** Капри на экране → анимация и панель; убрана в биочип или окно полноэкранное →
  системное уведомление (libnotify).

### 2. Arch Update Sentinel — **реализован** (`services/arch-sentinel.js`, tick раз в 3 ч)
- Сейчас: `checkupdates` + `paru -Qua`/`yay -Qua`; новости из RSS, вышедшие после последнего `-Syu`
  из `pacman.log` и называющие пакет из очереди целым словом; новые файлы из `pacdiff -o`; запущенное
  ядро без `vmlinuz` в `/usr/lib/modules`. `.pacnew` и ядро проверяются ещё и через 30 с после
  любой записи в `pacman.log`. Что уже показано — в `arch-sentinel.json` в userData.

Исходный замысел:
- `checkupdates` (без root, отдельная БД) → число обновлений и «опасные» пакеты (ядро, mesa, nvidia,
  systemd, glibc, hyprland).
- RSS `archlinux.org/feeds/news/`: если новость упоминает пакет из списка обновлений — предупредить
  **до** `-Syu` (ровно те новости, где «manual intervention required»).
- После обновления (событие из pacman-хука `/etc/pacman.d/hooks/capri.hook` → `capri_emit pacman.done`):
  поиск `.pacnew` (`pacdiff -o`), пересборка AUR против нового python/ядра, напоминание о
  перезагрузке, если обновилось ядро (`uname -r` ≠ модули в `/usr/lib/modules`).

### 3. System Health Watch (`services/health.js`, tick 60 с + `journalctl -f`)
- `journalctl -f -p err -o json` как долгоживущий поток → группировка по юниту, кулдаун 10 мин.
- `systemctl --user --failed` и `systemctl --failed`, новые записи `coredumpctl list --since`.
- Диск < 10 %, температура, OOM-kill (`journalctl -k` по `Out of memory`).
- Сообщает только **новое**: состояние хранится в `userData/health.json`, чтобы не повторять одно и то же.

### 4. Clipboard Inspector (`services/clipboard.js`, `wl-paste --watch`)
- Каждое копирование классифицируется **локально** (регулярки, без отправки куда-либо): стектрейс
  Python/Rust/JS, ошибка компилятора, вывод `journalctl`, JSON, JWT, хэш коммита, URL GitHub-issue.
- Если это ошибка — над биочипом загорается чип «разобрать?». В Groq текст уходит только по клику.
- Пароли из менеджеров не трогаются: события с MIME `x-kde-passwordManagerHint` пропускаются, есть
  чёрный список классов окон (keepassxc, bitwarden).

### 5. Workspace Presets + Context (`services/workspaces.js`, `presets.json`)
- Пресет = список окон с правилами: `{ "dev:capri": [{ "exec": "kitty -d ~/proj", "ws": 2 }, …] }`.
  Запуск по фразе в HUD или по событию.
- Автотриггер по socket2: открыл kitty в каталоге с `.git` и пресетом → предложить разложить
  остальное. Плюс напоминания: `capri_remind 40m "выкатить релиз"` → таймер в scheduler, переживает
  перезапуск (`userData/reminders.json`).

## Архитектура

```
              zsh-хук, pacman-хук, скрипты (capri_emit)
                              │  JSON-строки
                              ▼
      $XDG_RUNTIME_DIR/capri/events.sock ── services/ingress.js
                              │ bus.emit(type, ev)
                              ▼
  ┌──────────── services/index.js ────────────┐
  │ EventEmitter-шина + notice() с бюджетом     │◄── tick-сервисы (host.js:
  │ внимания (key-кулдаун, fullscreen → тихо)  │     интервал, без перекрытий, backoff)
  └──────────────────────┬─────────────────────┘
                         │ deliver(notice, { quiet })
                         ▼
          main.js: deliverNotice ──► 'capri:notice' ──► brain.notice()
                         └──────► Notification (биочип / fullscreen)
```

- **`services/host.js`** — event loop. Сервис: `{ name, start(ctx), stop(), every, tick(ctx) }`.
  Тики одного сервиса не перекрываются, ошибки изолированы и растягивают интервал (×2 до ×8).
- **`ctx`** — всё, что сервису можно: `bus`, `config`, `groq`, `hyprQuery`, `notice`. Сервисы не
  импортируют Electron, поэтому тестируются обычным `node` с подменённым ctx.
- **`notice`** — `{ kind, key, title, line, quote, reply, context }`. `context` уходит в историю
  диалога Капри: фоновое событие становится частью разговора.
- **`src/main/tools/`** — CLI для шелла и для самой Капри (уже есть `sys_info`, `media_control`…).
  Следующие: `capri_emit <type> [json]` (отправка события в сокет), `capri_remind`, `capri_preset`.

## Подключение watchdog

1. В конец `~/.zshrc` (строку можно скопировать из трея: «Фоновые функции → Скопировать строку»):
   ```zsh
   source ~/.config/capri-desktop/src/main/hooks/capri.zsh
   ```
2. Чтобы при падении был хвост вывода, в `~/.config/kitty/kitty.conf`:
   ```
   allow_remote_control socket-only
   listen_on unix:@kitty
   shell_integration enabled
   ```
   Без этого watchdog работает, но разбирает падение только по команде и коду выхода.
3. Трей → «Фоновые функции»: включение/выключение watchdog и разбора через Groq.

## Три главные функции

### Снимок поломки — `SUPER+SHIFT+X` (`tools/context_snapshot.js`)
Одним нажатием: активное окно, последние 30 строк терминала (kitty/wezterm через их API, tmux через
`capture-pane`, иначе OCR окна, у IDE — только нижняя часть, где встроенный терминал), буфер
обмена, git в каталоге терминала (ветка, status, конфликты, незаконченный merge/rebase, diff),
недавние упавшие команды от watchdog. Секреты вычищаются (`tools/lib/redact.js`), снимок сохраняется
в `userData/snapshots/` и сразу уходит в агентский цикл: причина + фикс. Патч применяется через
`git apply`, и в диалоге подтверждения виден весь дифф. Агенту доступна та же утилита:
`context_snapshot`.

### Разбор выделенного — `SUPER+SHIFT+R` (`tools/intent_router.js`)
Выделение (primary), иначе буфер → интент определяется на месте регулярками → материал:
GitHub/GitLab issue и PR (описание, статус, метки, комментарии; токен из `gh auth token`), видео
(метаданные, главы, субтитры через yt-dlp), страница (web_action), лог или файл, ошибка (+ git-контекст
терминала), просьба изменить код (→ патч), фрагмент кода. Ссылки, медиа и файлы — сразу выжимка;
ошибки и правки — в агентский цикл. Агенту доступна утилита: `intent_router '<текст>'`.

### Эко-режим игрока — `services/resource-sentinel.js`
Каждые 5 с (~17 мс на проверку): игра (reaper `SteamLaunch AppId`, `steam_app_*`, gamescope, `.exe`
во весь экран, `gameClasses`) или тяжёлая сборка (компиляторы при загрузке выше 75 % ядер).
Игра: уведомления копятся до конца, swaync/mako/dunst в «не беспокоить», `performance`, без
анимаций/размытия/теней, максимальная частота монитора, по желанию — SIGSTOP браузеров (кроме тех,
что играют звук; ANR-диалог выключается), `gameHooks`. Сборка: только `performance`. После —
откат в обратном порядке и сводка (время, батарея, пик нагрузки, t° CPU, что разморожено).
Журнал отката лежит на диске: если Капри упадёт посреди игры, при следующем старте всё вернётся.
Вручную: `game_mode on|off|status`.
